# Translation

i18next + react-i18next. English is both the source language and the
fallback, so a missing key renders the English string rather than
`sidebar.newChat` — a UI showing a key is worse than one showing the
wrong language, because the second is readable.

## The shipped set: one language per inhabited continent

| Continent | Language | |
|---|---|---|
| North America | English | `en` |
| South America | Español | `es` |
| Europe | Français | `fr` |
| Africa | Kiswahili | `sw` |
| Asia | 日本語 | `ja` |
| Oceania | Te Reo Māori | `mi` |

The continent is the **selection rule**, not a claim about where a
language is spoken — French is picked for Europe and is spoken across
West Africa; Spanish is picked for South America and comes from Spain.
The rule exists so the default set is not six European languages
chosen by whoever was in the room. `locales.test.ts` pins it, because
otherwise the next language added is whichever one somebody happened
to need and the set drifts back.

Antarctica has no indigenous language and no permanent population, so
there is nothing to pick. Saying that is more honest than shipping
five and calling it six.

**Every locale except English was authored by a model.** That is a
reasonable starting point and it is not the same as correct. Each
carries `reviewed: false` in `LANGUAGES`, the picker marks them with
an asterisk, and a fork putting one in front of real users should
have a speaker read the file first — it is about 120 strings.

## Adding a language

One file and two lines:

1. Copy `src/frontend/i18n/locales/en.json` to `<code>.json` and
   translate it.
2. Add it to `resources` and to `LANGUAGES` in
   `src/frontend/i18n/index.ts`.

Nothing else. A template whose translation story requires touching
five places does not get translated.

`src/frontend/i18n/__tests__/locales.test.ts` enforces the rest: every
locale must have exactly English's keys (none missing, no orphans),
must keep every `{{placeholder}}`, and must actually differ from
English — a locale copied verbatim passes every other check.

## Using it

```tsx
const { t } = useTranslation();
<button aria-label={t('sidebar.newChat')}>{t('sidebar.newChat')}</button>
```

Locales are bundled, not fetched: six small JSON files cost less
than a request waterfall and a loading state, and this runs behind a
login on a corporate network.

Language choice is stored in `localStorage`, so it is per-browser.
That is the honest scope — the agent has no user-preferences store the
UI can reach, and pretending otherwise would mean a setting that
silently fails to follow someone to a second machine.

`src/frontend/test-utils/setup.ts` initialises i18n for tests. Without
it, components render keys and every test matching on user-visible
text fails as soon as its component is translated — a failure in the
harness that looks like a failure in the UI.

## How far it got

Converted: sidebar, message input, chat message view, knowledge page,
analytics page, language picker — the surfaces a user looks at most of
the time.

Not converted: evaluation tooling, settings sub-panels and assorted
dialogs, mostly developer-facing.

```sh
npm run i18n:report                      # what is left, per file
node scripts/i18n-report.mjs --max=250   # ratchet, for CI
```

A count rather than a lint rule, on purpose. `jsx-no-literals` across
an unconverted codebase has to be switched off for most files, and a
rule that is off everywhere is not a rule. A number that has to go
down is one somebody can hold.
